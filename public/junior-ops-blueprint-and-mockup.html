Business Architecture Evaluation

Why Lead Source is the Heart of Operations Team Performance

In an interior design studio, not all leads are created equal. An Architect Referral converts in 12 days with high trust, while an Instagram inbound requires aggressive qualification to avoid wasting design resources. Evaluating an Ops member on conversion without factoring in Lead Source penalizes them unfairly or hides channel bottlenecks.

1. Developer Handover

Handover drives at Prestige, Sobha, DLF. High volume, strict move-in dates, society NOC dependent.

Ops KPI: Key to Kickoff <10d
2. Architect Referral

High ticket value (₹45L+). Ops must maintain white-glove comms and ensure strict drawing fidelity.

Ops KPI: Zero spec conflict
3. Past Client Referral

80%+ closing rate. Fast track onboarding and personalized gift kit within 24h.

Ops KPI: 100% On-time survey
4. Instagram / Social

Visual curiosity. Ops must respond in <15 mins and qualify budget fit before booking 3D designers.

Ops KPI: First response <15m
5. Website Organic/Ads

High search intent. Immediate portfolio dispatch and discovery call scheduling.

Ops KPI: Discovery booked in 24h
Engineering Roadmap

Phased Implementation Plan: From Types to Production UI

Concrete plan adhering strictly to the Working Agreement (no router, Tailwind in HTML, Lucide icons, Framer Motion, TypeScript, dbService persistence).

Phase 1: Types & Domain Model Extension (`types.ts`) TYPES LAYER

• Add `LeadSourceType = 'developer_tieup' | 'architect_referral' | 'past_client' | 'instagram' | 'website_organic' | 'walk_in' | 'broker'` to `types.ts`.
• Extend `ProjectContext` and `LeadProfile` with `leadSource: LeadSourceType`, `referralPartnerName?: string`, and `leadAttributedToUid?: string`.
• Add `TouchpointLogRecord` interface: id, projectId, coordinatorUid, channel, sentiment ('green' | 'amber' | 'red'), summary, nextActionDate, leadSource, timestamp.
• Add `PreSiteChecklistState`: societyNocDone, elevatorPaddingDone, keysDeposited, utilitiesActive, briefSigned, advanceVerified.

Phase 2: RBAC Hard Security & Tab Permissions (`lib/roleAccess.ts`) SECURITY LAYER

• Register `UserRole = 'Ops Coordinator'` in `types.ts` and `lib/roleAccess.ts`.
• In `roleAccess.ts`: grant active access to `home`, `clients`, `onboarding`, `mom-action-tracker`, `handover-docket`, `drawing-tracker`.
• Maintain strict financial isolation: `FINANCE_TABS` blocks `ops` (pricing), `analytics` (margins), `reports` (studio P&L), and item bank buy rates.

Phase 3: Global Sidebar & Routing Integration (`components/Header.tsx` & `App.tsx`) ROUTING LAYER

• In `components/Header.tsx`: ensure `Ops Coordinator` sees `Home`, `Projects`, `Clients` in the `STUDIO` section.
• In `components/StudioHomeOrbit.tsx`: render the tailored **Coordinator Daily Cockpit** when `currentRole === 'Ops Coordinator'`.
• In `components/ClientsTab.tsx`: add segmented sub-navigation for *1. Client Directory*, *2. Lead Source Attribution & Follow-up Radar*, and *3. Daily Activity Scorecard*.

Phase 4: Component Implementation (`components/ops/*`) UI COMPONENTS

• Create `components/ops/LeadSourcePerformanceLedger.tsx` for channel win rates & cycle times.
• Create `components/ops/ClientTouchpointLoggerModal.tsx` for frictionless 30s interaction capture.
• Upgrade `components/onboarding/OnboardingTab.tsx` with the 6-step gated pre-site readiness pipeline.
• Upgrade `components/MomActionTracker.tsx` with direct Drawing Sheet ID and Room action tagging and WhatsApp MoM card generator.
• Build `components/ops/EODDigestModal.tsx` for 1-click WhatsApp/Slack daily summary generation.

Phase 5: Persistence & Audit Layer (`services/dbService.ts`) STORAGE & AUDIT

• Persist touchpoints into `organizations/{orgId}/touchpoints` subcollection or project context with cryptographic audit trail.
• Track EOD submissions in `organizations/{orgId}/eodReports`.
• Ensure full offline fallback to `idb-keyval` when running without active Firestore connection.
